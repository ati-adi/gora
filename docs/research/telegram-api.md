# Research: telegram-api

## Summary

Telegram Bot API reference for Gora, current as of 2026-09-28. I pulled core.telegram.org/bots/api, /bots/api-changelog, /bots/features, /bots/webapps (which also returned the Bots FAQ and the Telegram Login/OIDC page) and /bots/payments-stars with curl, plus the 2026 Telegram blog posts and telegram.org/tos/bot-developers. I also checked the published grammY 1.46.0 and @grammyjs/types 5.0.0 packages from npm. The newest Bot API version is 10.3 (Aug 24, 2026). There is no September 2026 changelog entry.

The main AI-agent building blocks, by version:
- Streaming: sendMessageDraft arrived in 9.3 (Dec 31, 2025) and at first worked only for bots with forum topic mode on (confirmed in a Feb 2026 Wayback snapshot). 9.5 (Mar 1, 2026) opened it to all bots. 10.0 allows empty text, which shows a "Thinking…" placeholder. 10.1 added sendRichMessageDraft. 10.3 added a user Stop button (can_stop, keep_on_stop) and the Update.stopped_message_generation update. Streaming works only in private chats: there is no business_connection_id parameter, and a draft is a 30-second temporary preview that you must persist with sendMessage or sendRichMessage.
- Rich messages (10.1–10.3): GitHub-style Markdown or HTML or explicit blocks, with tables, task lists, LaTeX, details blocks, media, maps and in-message buttons. Up to 32,768 characters and 500 blocks. Also usable as guest, inline and Mini App results.
- Guest mode (10.0, May 8, 2026): turn on "Guest Mode" in the BotFather Mini App. The bot gets Update.guest_message and replies once via answerGuestQuery(guest_query_id, InlineQueryResult), which returns an inline_message_id. It sees no chat history and no member list, and up to 3 guest bots can be mentioned in one message.
- Chat Automation, also called secretary or business bots: turn on "Secretary Mode" in BotFather; users connect under Settings > Chat Automation. Since 10.0 no Premium subscription is needed. It uses the business_connection, business_message, edited_business_message and deleted_business_messages updates. The BusinessBotRights object has 14 flags (introduced in 9.0). can_reply only works in private chats that had an incoming message in the last 24 hours, and readBusinessMessage has the same 24-hour rule.
- Bot-to-bot communication (10.0): turn on "Bot-to-Bot Communication Mode". Works in groups, by sending to "@otherbot" directly when both bots have it on, and through business connections. Loop safeguards are required.
- Private-chat topics: 9.3 made topics work in private chats and 9.4 added createForumTopic there. It is turned on as "Threaded Mode" in the BotFather Mini App; that setting name comes from third-party (Hermes) docs.
- Checklists (9.1): sendChecklist and editMessageChecklist only work on behalf of a connected business account.
- Stars payments: subscriptions are created only with createInvoiceLink and subscription_period=2592000. Update.subscription arrived in 10.2.
- Other: ephemeral group messages (10.2/10.3), managed bots (9.6/10.0), and Mini App hardening (10.2) that blocks calls from other origins, enforced from July 20, 2026.

grammY 1.46.0 supports Bot API 10.3, including ctx.replyWithDraft, replyWithRichMessageDraft, answerGuestQuery, and the guest_message and stopped_message_generation filters. @grammyjs/stream 1.1.0 adds replyWithMarkdownStream. The Bot Developer ToS adds hard rules for an AI agent: section 5.4(iv) forbids passing Business message contents to third-party APIs without the user's authorization, and 4.2–4.4 require deletion on request, explicit consent and encryption at rest.

Each fact below is marked verified (I read it in the source text), likely or uncertain.

- **[verified] 2. Guest mode - semantics and limits**: A user triggers the bot by mentioning @botname in 'any private or group chat', or by replying to one of its messages. The bot 'receives a dedicated update and is able to issue one reply'. The update includes the summoning message and, when present, the message it replied to. 'Guest mode does not grant access to a chat's message history or participant list'. The bot gets no further updates unless mentioned or replied to again. Up to 3 guest bots per message. Blog: 'Bots only have access to the specific message they are tagged in and any replies to that message. Bots cannot see which users are in the chat'. Chat ids: 'If [guest_query_id is] non-empty, the message belongs to the chat where the guest bot was summoned, which may not coincide with other existing bot chats sharing the same identifier.' Channels are not mentioned. _(source: https://core.telegram.org/bots/features#guest-bots ; telegram.org/blog/ai-bot-revolution-11-new-features ; /bots/api#message)_

- **[verified] 3. Business - ToS obligations (critical for an LLM agent)**: Bot Developer ToS 5.4: (i) truthfully represent the scope of services; (ii) clearly state what private data is retained, for how long and why; (iii) never use Business message contents for any purpose other than the chatbot service; (iv) 'never disclose message contents, files or other data you obtained or processed through or in connection with Telegram Business to third parties (including third-party APIs) without the user's authorization'; (v) never conceal activity from the account owner; (vi) notify users of significant changes. 5.2: 'cannot use its privileges (... private chat management via Telegram Business, etc.) to carry out actions that diverge from the purposes under which the privileges were originally obtained'. 4.2: delete user data on request or when no longer needed. 4.3: no collection for ML datasets; use of data submitted directly requires 'individual, explicit, active and revocable consent'. 4.4(a): user data must be 'encrypted at rest and stored separately from its encryption key'. _(source: https://telegram.org/tos/bot-developers)_
- **[verified] 4. Bot-to-bot communication**: Bot API 10.0. Enable 'Bot-to-Bot Communication Mode' in BotFather. Private chats: 'Bots can send private messages to other bots by passing their @username to the sendMessage method' (chat_id '@otherbot'); both bots need the mode on. ## Implications for Gora

- Streaming UX: in the private DM, stream with sendRichMessageDraft using the markdown field, since Claude's GFM output maps almost 1:1 onto Rich Markdown and avoids MarkdownV2 escaping. Keep one non-zero draft_id per generation so updates animate, then persist with sendRichMessage. If rich parsing fails, fall back to plain sendMessage with no parse mode.
- Keep drafts alive: a draft is a 30-second preview, so during long tool calls re-send the same draft_id at least every ~20 s with a status line (for example a <tg-thinking> block such as 'Checking flights…'). Throttle updates to roughly 1 per 0.5–1 s per chat (no official limit is documented), and use @grammyjs/auto-retry for 429 errors.
- Always pass can_stop:true. Keep a map from (chat.id, message_thread_id, draft_id) to an AbortController, and on stopped_message_generation abort the Anthropic stream and background tool work. With keep_on_stop the partial text disappears unless you resend it as a real message, so send the partial text as a new message if the user should keep it.
- Outside the private DM (guest replies, groups, business chats), streaming is impossible. Use 'send short placeholder, then editMessageText' (by inline_message_id for guest replies), or send a single final message.
- Topics as task workspaces: require 'Threaded Mode' in BotFather (fail fast at startup by checking getMe().has_topics_enabled). createForumTopic per long-running task or project, and use message_thread_id as the session key (user_id, thread_id). Background tasks post results into their own topic. When ForumTopicCreated.is_name_implicit is set, auto-rename the topic with editForumTopic using an LLM-generated title. closeForumTopic may not work in private chats, so mark completion with a rename or emoji icon instead.
- Namespace every chat key by context. The docs say chat ids from guest_message (guest_query_id) and from business messages (business_connection_id) are independent of the bot's own chat with the same id. Suggested SQLite key: (context_kind in {dm, business, guest, group}, business_connection_id?, chat_id, thread_id?).
- Guest mode ('@gora …' in any chat): exactly one answerGuestQuery per summon. For quick tasks answer directly with InlineQueryResultArticle plus InputRichMessageContent. For long tasks answer at once with a placeholder and an inline 'Open in Gora' deep-link button (t.me/<bot>?start=...), then edit via inline_message_id when done. Treat the guest message and any replied-to message as untrusted input (prompt-injection surface), since the bot sees nothing else from that chat.
- Secretary / Chat Automation mode: enable Secretary Mode, and handle business_connection to persist the connection's id, rights, is_enabled and user_chat_id. Gate every action on the current rights. can_reply only works where there was an incoming message in the last 24 h, so the agent cannot open new conversations on the user's behalf. readBusinessMessage also has a 24 h window. Treat the '/start bizChat<id>' deep link as the entry point to a per-chat settings screen.
- ToS 5.4(iv) plus Muse-style approvals: get explicit, recorded user authorization before sending any Business message content to the Anthropic API. Show a proposed reply in the DM (or its topic) with Approve (style success), Edit and Reject (style danger) inline buttons before sending with business_connection_id. Log every business action to an audit table, and tell owner-sent from bot-sent messages apart via sender_business_bot and from.id == connection.user.id.
- Compliance by design: encrypt stored user data and memories at rest with the key kept separately (ToS 4.4a); implement a real '/forget' and 'delete my data' (4.2); take explicit consent for memory use (4.3); never use user data for training. These map directly to the Muse features 'forget specific memories' and 'audit trail'.
- Native checklists (sendChecklist) exist only on behalf of a business account. In the bot DM, show tasks as rich-message task lists ('- [ ]') plus inline buttons or the Mini App, and track state in SQLite. Use checklist_tasks_done updates only in business contexts.
- Monetization: sell Gora tiers with Stars only (XTR, one LabeledPrice). Create subscriptions with createInvoiceLink(subscription_period=2592000, price ≤10000 Stars) and open them from the Mini App via openInvoice or from a URL button. Answer pre_checkout_query within 10 s from a fast path (no LLM). Deliver only on successful_payment; store telegram_payment_charge_id; handle Update.subscription states canceled/active/failed; implement /paysupport (required) and /terms; support refundStarPayment and editUserStarSubscription. Purchases the agent makes for the user in the outside world (Stripe Link and similar) are a separate concern from paying for Gora itself.
- Mini App (React+Vite, same Node process): open it from the menu button or Main Mini App or an inline web_app button, never from a reply-keyboard web_app button, whose initData is empty. Validate initData server-side with HMAC (node:crypto) on every API call and reject stale auth_date (for example older than 1 h for sensitive actions, 24 h for reads). Serve the Mini App and its API from the exact origin registered in BotFather because of the July 20, 2026 origin lock. Use SecureStorage (10 items) for device-bound secrets, CloudStorage for small prefs, LocationManager for location-aware proactivity, requestWriteAccess to guarantee proactive DMs are allowed, and addToHomeScreen for app-like access.
- Proactive messaging and background tasks: enforce a per-chat queue (≤1 msg/s per chat, ≤20/min per group, ≤30/s global) with a token bucket (@grammyjs/transformer-throttler plus auto-retry).
