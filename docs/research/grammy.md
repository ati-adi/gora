# Research: grammy

## Summary

I checked everything against the npm registry, GitHub releases, core.telegram.org (Bot API changelog, API reference, features and webapps pages) and the grammY docs sources on 2026-09-28. I also installed the packages in a scratchpad and ran mock-only probes on Node 26.8.1, typechecked with tsc 7.0.2.

**Versions**
- grammy@1.46.0 (2026-08-26) is the latest. It pins @grammyjs/types@5.0.0 and fully types Bot API 10.3 (2026-08-24).
- Fully typed, so no raw casts needed:
  - Guest mode: the guest_message update and answerGuestQuery.
  - The stopped_message_generation update.
  - sendMessageDraft with can_stop/keep_on_stop.
  - Rich messages (Bot API 10.1+): sendRichMessage and sendRichMessageDraft, with rich_message {markdown|html|blocks}, and an editMessageText rich_message param.
  - Ephemeral messages, managed_bot, subscription, and all business updates and methods.
- grammY context helpers exist:
  - ctx.guestMessage, ctx.answerGuestQuery, ctx.stoppedMessageGeneration
  - ctx.replyWithDraft, ctx.replyWithRichMessage, ctx.replyWithRichMessageDraft
  - ctx.businessConnectionId. ctx.reply adds business_connection_id automatically.

**Streaming**
- Official plugin: @grammyjs/stream@1.1.0.
  - ctx.replyWithMarkdownStream(asyncIterable) sends sendRichMessageDraft repeatedly, then one final sendRichMessage.
  - It is recommended together with @grammyjs/auto-retry.
- Telegram parses Rich Markdown itself. It is GitHub-flavoured Markdown (GFM) with tables, headings, task lists, LaTeX and footnotes, up to 32768 chars. This is now the robust way to send LLM output in private chats.
- Drafts work only in private chats, have no business_connection_id, and last 30 seconds each.
- Fallback when Rich Markdown can't be used: telegram-md-entities@0.6.0, which turns Markdown into {text, entities} with no parse_mode.

**Webhooks and polling**
- webhookCallback(bot, "hono", {secretToken}) works with hono@4.13.9 and @hono/node-server@2.1.1: 200 with the secret, 401 without.
- The webhook default timeout is 10s, and Telegram sends one chat's updates one at a time. So the webhook must acknowledge fast and queue the work.
- For long polling: @grammyjs/runner@2.0.3 with run() and sequentialize(). Returning undefined from sequentialize for stop and callback updates lets them skip the per-chat queue, so they can cancel a running turn.

**Testing**
- This pattern works with no network:
  - `new Bot(token, {botInfo})`, so there is no getMe call.
  - `bot.api.config.use(fakeTransformer)` returns `{ok:true, result}` and records each call.
  - `await bot.handleUpdate(fakeUpdate)`.
- The transformer installed last runs first. Install the fake one first so the real autoRetry wraps it.
- 429 retries and 400 GrammyError both work in the mock.

**Mini App**
- @telegram-apps/init-data-node is deprecated in favour of @tma.js/init-data-node@2.0.8.
- A hand-rolled node:crypto HMAC check was cross-checked against tma.js sign/validate and agrees.
- Frontend options:
  - Lightest: telegram-web-app.js?63 with @types/telegram-web-app@10.1.0.
  - Or @tma.js/sdk-react@3.0.23. @telegram-apps/sdk-react@3.3.9 is abandoned (last release 2025-10).
- typescript@7.0.2 is the native Go compiler. Use it for typechecking only. Node 26 runs .ts directly.

- **[verified] @grammyjs/stream plugin**: @grammyjs/stream@1.1.0 (2026-06-19, peer grammy ^1.39.0). Usage: `type C = StreamFlavor<Context>; bot.api.config.use(autoRetry()); bot.use(stream());` Context methods:

Verified call sequence: sendRichMessageDraft {draft_id:1, markdown:'Hello **wor'} → sendRichMessageDraft {'Hello **world**'} → sendRichMessage {markdown:'Hello **world**'}.
Behaviour:
- Accumulates chunks and sends drafts as fast as the previous call completes, skipping intermediate states (no timer throttle).
- If the passed AbortSignal is aborted, the final sendRichMessage is also aborted (partial text lost). To stop gracefully, end the async iterator instead (abort the Anthropic stream) and the plugin persists the partial text.
- If you pass the options object it must include draft_id: `ctx.replyWithMarkdownStream(gen, { draft_id: ctx.update.update_id, can_stop: true })`.
